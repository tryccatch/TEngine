项目采用 Unity 标准 Assets 目录结构，按职责划分为四个核心层次：
- `Assets/TEngine/`：自研框架库，通过 Runtime（ModuleSystem + 各 Module：Audio/Resource/Procedure/Fsm/Localization/ObjectPool/Timer/Debuger 等）+ Editor（构建工具、Inspector、AtlasMaker、LubanTools、ReleaseTools、Localization 编辑器）+ Extension（HtmlToUGUI、InputSystem）三层组织，以 asmdef 隔离 `TEngine.Runtime` 与 `TEngine.Editor`。
- `Assets/Launcher/`：冷启动入口，`GameEntry.cs` 在 Awake 中通过 `ModuleSystem.GetModule<IUpdateDriver>` 等初始化框架模块并调用 `Settings.ProcedureSetting.StartProcedure()` 进入流程；`LauncherMgr` 管理 UI 窗口生命周期，依赖 `Resources.Load` 加载 `UIWindow/` 下的预制体。
- `Assets/GameScripts/HotFix/`：热更新代码域，`GameLogic` 使用自定义 SingletonSystem 与 IEvent 事件总线，`GameProto` 包含 LubanLib 协议序列化基类，二者均通过 asmdef 独立编译为热更 DLL。
- `Assets/GameScripts/Procedure/`：基于 FSM 的流程状态机，每个 `ProcedureXxx.cs` 继承 `ProcedureBase`，由 `ProcedureModule` 驱动执行下载、预加载、资源初始化等阶段。

依赖方向单向：Launcher → TEngine.Runtime → HotFix(GameLogic/GameProto)；Editor 仅依赖 Runtime，不反向依赖业务。构建产物通过 YooAsset 打包到 `Bundles/Android/DefaultPackage/Simulate/`，由 `HybridCLRSettings.asset` 与 `package.json` 声明包元数据。
